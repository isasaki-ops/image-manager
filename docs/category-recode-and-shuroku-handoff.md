# イベントコード仕様変更のお知らせ（新カテゴリ「収録」追加）

宛先: **東北スタッフ申請アプリ開発側**
起票: image-manager側（2026-08-27）

## 背景

image-manager（取材画像管理ツール）に新しいイベントカテゴリ「収録」（`category_id = '03'`）を追加します。
これに伴い、イベントコード（`event_code`）の採番方式を変更しました。

## 変更点

### 1. 新カテゴリ「収録」の追加

`event_code`が`03-`で始まるイベントが今後登場します。

| プレフィックス | カテゴリ |
|---|---|
| `01-` | 取材（イベント） |
| `02-` | 来店（演者） |
| `03-` | 収録（**新規**） |

現状の連携APIで収録イベントも取り込む必要があるかどうかは、そちらの案件区分の運用に合わせて判断してください。プレフィックス判定ロジックに`03-`のケースを追加するか、無視して構わないかご検討をお願いします。

### 2. 【重要・一度きりの変更】既存event_codeの番号が振り直されます

これまで`event_code`の4桁部分はカテゴリ（`01`系・`02`系）ごとに別々の連番で管理していたため、
`01-0100`と`02-0100`のように**異なるイベントで番号が重複するケース**がありました。

これを解消するため、デプロイ時に**既存の全イベントのevent_codeの4桁部分を、登録日時順の重複しない連番に振り直します**（プレフィックスの`01`/`02`の意味自体は変わりません）。

例: `02-0141` → `01-0187`（カテゴリ`02`のまま、番号だけ変わる場合もあれば、番号もカテゴリも変わらない場合もあります）

**そちら側で`event_code`を保存・キャッシュしている場合**、デプロイ後に一度**差分取得ではなく全件取得**で同期し直してください。`event_id`（UUID）をキーにした紐付けには影響ありません。

### 3. 今後のカテゴリ変更時の挙動変更（参考情報）

これまでイベントのカテゴリを変更すると、`event_code`の番号部分も新しく採番し直されていました（プレフィックスだけでなく番号も変わっていました）。

今後は、**カテゴリを変更しても番号部分は維持され、プレフィックスだけが新カテゴリの値に変わります**（例: `02-0184`を取材に変更すると`01-0184`になる）。

そちら側が`event_code`の先頭2桁だけを見て取材/来店を判定しているのであれば、この変更による影響はありません。

## 反映タイミング

デプロイ完了後、上記2番の一括振り直しが1回だけ実行されます。反映後にそちらの管理画面で全件同期をお願いします。
